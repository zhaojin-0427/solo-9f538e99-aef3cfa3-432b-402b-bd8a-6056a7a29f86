# 病理图像训练/验证清单划分系统

Flask + SQLite 单容器应用：上传全量图像 CSV 与重复图像关系 CSV，按各类别验证张数配额，
把图像划分为**训练侧**与**验证侧**两份可下载清单。

## 核心业务规则

1. **连通分量是最小分配单元**：同一患者的所有图像、以及重复图像关系 CSV 中连通的图像
   （并查集合并，含传递链）必须整体在同一侧。
2. **精确满足配额**：验证侧每个类别的图像张数必须与填写的配额**精确相等**；
   多维 0/1 背包 DP 在 ≤40 张、≤4 类的状态空间内求精确解。
3. **侧别永久固定**：成功发布即把每张图像的侧别写入全局唯一的 `side_registry` 登记表。
   之后即使删除数据重新上传同一图像，其侧别也不会改变；新划分必须服从登记。
   - **按真实图像身份登记**：CSV 解析严格按“已识别的表头列序”取字段（中英文表头、
     BOM、GBK、无表头按列序），不会因为表头换了列序就把患者号登记成图像号。
   - **历史证据优先于旧登记键**：启动时会依据原始 CSV 全文与原发布明细
     （`manifest_entries` 原始编号）还原真实图像的**历史侧别**，不信任旧登记键；
     即使图像已从当前版本删除，其历史仍被保留。
   - **无法唯一对应 / 一图曾发布到两侧**：保留逐条证据（`legacy_identity_records`）
     与冲突记录（`identity_conflicts`），**不进入任一侧登记**；任何涉及该图像的
     连通分量在划分时判 **关联冲突**，绝不任选一侧。
   - **受影响旧清单停供**：原清单编号与原始明细原样保留，`published` 状态记录保留，
     仅标记停供（`quarantined=1`）并给出可查原因（历史页 / 版本详情 / 登记页）；
     未受影响的当前清单照常供数。停供清单不占用“每版本唯一可下载清单”和
     “活动作业”唯一位，因此同一版本可按真实身份重新划分并发布干净清单。
4. **无解不发布**：
   - *关联冲突 (conflict)*：一个连通分量内的已发布图像被固定在不同侧，或涉及
     历史证据无法唯一确定侧别的图像；
   - *配额不可达 (quota)*：锁定图像已超配额，或自由分量不存在精确凑出配额的组合。
   页面给出人类可读原因 + 结构化诊断（最接近的可达组合、自由分量向量等），不产生清单。
5. **更正即新版本**：重新上传 CSV 或修改配额都会生成新输入版本，旧版本立即变为
   `superseded`，旧清单仅作历史保留、**下载停供**；新版本重新划分成功后下载才恢复。
6. **求解期间可更正，过期依据不发布**：作业发布前复查版本新鲜度，版本已过期则判 `stale`
   失败，不写任何分配。
7. **并发与原子性**：
   - 部分唯一索引保证同一版本至多一份可下载清单、至多一个未作废的活动作业；
   - 清单、明细、侧别登记在单个 `BEGIN IMMEDIATE` 事务内提交，失败整体回滚，
     不会留下半次分配；
   - 服务重启时残留的 `queued/running` 作业一律标记 `restart` 失败（它们从未写入分配）。
8. **旧数据升级（一次性、原子、可重试）**：
   - 启动时在单个 `BEGIN IMMEDIATE` 事务内完成；任何一步失败整体回滚、不写迁移标记，
     不会留下部分修复，下次启动自动重试；成功写入 `schema_migrations` 后反复重启不再执行
     （多进程同时启动也只有一个执行）。
   - 原始输入（`input_versions.image_csv`）、原发布明细（`manifest_entries`）与所有编号
     一律不改；旧登记键完整留档到 `legacy_registry_archive`；仅重建派生的 `images` /
     `dup_edges` 与真实身份登记。
   - 新旧记录混存、反复重启、更正与发布交错时判定仍然成立（回归测试覆盖）。
9. **规模限制**：最多 40 张图像、4 个类别。

## 目录结构

```
app/
  db.py        SQLite 建表、索引、连接、列升级与重启恢复
  migration.py 一次性旧数据身份还原（原子、可重试、可查证据）
  parser.py    CSV 解析（严格按识别出的表头列序）、输入校验、并查集
  solver.py    历史证据冲突 + 锁定校验 + 多维 DP 精确配额 + 无解诊断
  service.py   输入版本、作业调度、原子发布、历史与下载
  web.py       Flask 路由
  templates/   中文网页（当前版本/作业原因/历史/永久登记/证据）
wsgi.py        waitress 生产入口
tests/         pytest（求解器、端到端、旧数据升级、证据与冲突）
samples/       示例 CSV
Dockerfile, docker-compose.yml
```

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8080
```

SQLite 数据保存在命名卷 `pathology_data`（容器内 `/data/pathology.db`），重启不丢。
健康检查由 Compose / Dockerfile 内置。

## 本地运行（无 Docker 时）

```bash
pip install -r requirements.txt
DB_PATH=./data/pathology.db python wsgi.py
# 自测：
PYX_SYNCHRONOUS=1 python -m pytest tests/ -q
```

## CSV 格式

全量图像 CSV：首行表头可省略。**表头顺序可以任意**，解析按识别到的表头列名取字段；
无表头时才按 `图像号,患者号,类别` 的列序读取。

```
图像号,患者号,类别
IMG001,P001,肿瘤
IMG002,P001,肿瘤
```

以下列序同样正确解析（旧版本会在此把患者号当成图像号）：

```
患者号,图像号,类别
P001,IMG001,肿瘤
```

重复图像关系 CSV（可不上传，表头顺序同样按列名解析）：

```
图像号A,图像号B
IMG003,IMG006
```

## 页面操作

- **当前版本 `/`**：上传/更正 CSV、填写各类验证张数、发起划分、查看当前清单与下载两侧 CSV；
  旧清单因历史身份还原停供时，在此显示停供原因与重新划分入口；
- **作业页 `/jobs/<id>`**：求解状态自动轮询；失败时展示关联冲突/配额不可达原因与诊断；
- **历史 `/history`**：所有输入版本、作业（含失败原因）、已发布清单、**受影响旧清单的停供原因**、
  **历史证据冲突**与**逐条旧明细还原证据**；历史版本与被停供清单下载停供；
- **永久侧别登记 `/registry`**：全局图像侧别锁定表；未决的历史证据冲突单独列出（未登记任一侧）。

下载文件为 UTF-8 CSV：`图像号,患者号,类别,侧别,连通分量`。

## 环境变量

| --- | --- | --- |
| `DB_PATH` | `/data/pathology.db` | SQLite 数据库路径 |

| `SECRET_KEY` | 开发占位 | Flask 会话密钥，生产请覆盖 |
| `PYX_SYNCHRONOUS` | `0` | `1` 时作业同步执行（测试用） |
